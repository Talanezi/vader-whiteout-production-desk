## Workspace and data

The Shot Grid now uses TanStack Table **8.21.3** for column geometry, order and visibility. Whiteout still renders all controls and cells. Fixed readable column widths expand the canvas; native overflow, Shift-wheel and keyboard scrolling retain pinned grip/selection and shot identity. Boundaries resize by pointer or keyboard, double-click autofits with a cap, and the searchable column manager provides individual/all-width resets, order changes and presets. Personal layout preferences are sanitized and stored per user in browser storage, outside Yjs.

Essentials, Cinematography, AD / Planning and Full Technical are views over the same master records. AD / Planning includes derived dates, assignment count and status. Focus mode restores the previous rail/inspector state. Rows use compact technical cells, wrapping text previews and the existing collaborative CodeMirror editor on activation. At more than 250 rows, TanStack Virtual **3.14.24** windows measured rows; the ordinary 129-shot workbook does not need virtualization. Active editing and dragging rows stay mounted.

The grid owns navigation while cells own editing. Arrows, Home/End, Page Up/Down, Enter/F2, Escape, Tab, Shift ranges, native input undo and shared command undo have explicit boundaries. Quoted TSV preserves multiline text, tabs and empty cells. Multi-cell paste validates the entire matrix before one Yjs transaction. Invalid numeric fields, oversized data and derived-field edits fail without partial changes. Checkboxes, Shift row selection, rectangular cell selection, copy, duplicate, bulk field change and assignment share the existing selection rather than recreating it in export.

Dedicated grips use the current **@dnd-kit/react / @dnd-kit/dom 0.5.3** API, with 6px pointer activation, delayed touch activation, keyboard sorting, overlay/drop feedback, cancellation and reduced-motion handling. Optimistic sortable indices are resolved against stable UUID snapshots. Cross-scene and filtered drag ambiguities are blocked. Content remains live during sorting; only its presentation order is held while dragging. Scene, creative planning and shooting-order moves change separate order values. New labels use scene-A…Z, AA; imported labels stay exact text, including unusual or repeated historic labels. Duplication receives a distinct label. Deleted labels remain reserved for safe restore.

The additive `shootDays` and `shootAssignments` Y.Maps reuse the existing saved document state. No SQL schema migration is required. Days store real date-only values; assignments reference permanent master shot UUIDs, with their own order, notes, status, estimate override and pickup flag. Pickups can reference the same shot on another day. Removing an assignment/day does not delete or renumber a master shot. Shooting Order, totals, unscheduled assignment and reassignment all use these references. See `M032-SCHEDULING-CONTRACT.md` for the future read-only M05 contract; no M05 implementation is included.

Document indexes remove repetitive file icons and show actual scene/shot counts plus scheduled date ranges. Unscheduled lists say **Not scheduled**. An optional initial date never defaults to today or masquerades as an assigned shooting date. Existing Create/Metal, sidebar, title typography, Copy Link, inline Delete, toast system and inspector aesthetic remain in place. Call Sheet editor, roster and Scheduler source are unchanged.

## Print-area system and engine decision

**XeLaTeX remains the PDF generator. PDF.js 6.4.299 only renders the generated PDF for preview.** There is no browser screenshot export, new spreadsheet engine, Rust runtime or second PDF generator. `geometry`, `longtable`, explicit widths and repeated headers produce the primary compact **Table Print**. The prior narrative renderer remains the explicit **Detailed Production Report** alternate.

One versioned export specification resolves six scopes: Entire Shot List, Current View / Current Scene, Selected Shots, Selected Area, Selected Scenes and Selected Shoot Day. The frontend sends ordered stable shot/assignment UUIDs and field identifiers/relative widths; it sends no authoritative cell content. An actual rectangular selection carries its exact row range and displayed field order into the dialog. Selected Area is disabled when no valid rectangle exists. Existing checkbox selection is recognized immediately. Scene/day scopes resolve from current records; master numbers never change to match shooting sequence.

The existing HTTP guard and production-team policy authorize the document. The backend waits for queued saves, reads the authoritative persisted Yjs state into an isolated snapshot, validates every requested reference and field, and preserves the supplied order. Deleted or mismatched references fail clearly. Shot identity is retained when a range omits it. Table Print contains only chosen fields: hidden camera/focus/lighting notes are not automatically appended. The column chooser starts from the current grid. Relative widths are translated to paper proportions rather than copying CSS pixels directly.

Letter/A4, landscape/portrait, 12mm/8mm margins, fit one page wide, actual size and readable horizontal bands are supported. Fit-to-width continues vertically; it does not compress all rows onto one page. It refuses type below 8pt and offers fewer columns or readable bands. Bands repeat shot identity and are ordered down then across. Full text wraps and very long fields use continuation rows. The optional one-line mode explicitly warns that text is truncated; identifiers remain complete. Unsupported font characters return an explicit error rather than silently missing glyphs.

The preview canvas is rendered from the actual PDF bytes with page count, paper dimensions, page navigation and zoom. Download uses that same immutable Blob. Settings changes invalidate download until regeneration. Newer document edits display a banner explaining that the current download retains the preview snapshot until refreshed. Browser QA compares SHA-256 values before and after a collaborator edit.

Compilation uses isolated temporary directories, no shell escape, safe TeX escaping, restrictive file policies, 25-second pass timeouts, two concurrent jobs and bounded input/output. DejaVu Sans is embedded. Docker adds XeTeX and DejaVu; the existing Call Sheet pdflatex pipeline is preserved.

## Spreadsheet import

Upload → Map → Review → Import accepts XLSX, CSV and TSV, including UTF-8/UTF-16 text. SheetJS **0.20.3** remains the parser. Classifiers distinguish scenes, combined masters, planning blocks, references, templates and unknown sheets. Users can correct header rows, roles, mappings, timing units, scene IDs and exact shot text before confirmation. Manual reviewed corrections survive remapping. A downloadable CSV template is optional.

Every imported row keeps source-cell `t`, `v`, `w`, `z` and `f` plus original text in an audit field. Formatted identifiers are preserved. Numeric coercion that already occurred in the original workbook cannot be reversed reliably, so the workflow requires explicit review rather than guessing. Excel serial durations and explicitly selected seconds/minutes normalize deliberately. Six parallel shooting-order blocks in the original workbook remain excluded until a date and review are supplied; they reference existing masters instead of copying shots.

Preflight limits bound file size (8MB), ZIP inflation (64MB), sheets, rows, columns, candidates, text length and mutation budget. Backend import prevalidates all records before mutation and uses a batch UUID for idempotent retries. Import does not evaluate formulas. Failed confirmation retains review for a safe retry; this is not an offline import-resume system.

## Release and practical limits

Release uses source **main** → Railway backend, then a **fresh** production Vite build at `/productiondesk/` against the Railway HTTPS API → `vader-whiteout-site/productiondesk/` → website **main** / GitHub Pages. `qa/release.cjs` verifies base/API, no localhost/fixture leakage, exact copied hashes, removal of old compiled assets and unchanged files elsewhere in the site. Scheduler requires no new deployment, credentials or membership-policy change. No production SQL migration or historical workbook import is part of this release.

Read-only production hashes and counts are captured before/after: the existing `Whiteout — Shot List` was empty at baseline, with 8 Call Sheets and 26 roster records. Production verification uses the owner's normal signed-in session, existing document discovery, WebSocket Saved/reload, PDF preview/download and local import preview without confirming production import. Multi-shot mutations and multi-user editing are tested against disposable local PostgreSQL rather than modifying this empty production document for evidence.

Remaining practical limits: very wide selections intentionally require horizontal bands; unsupported font glyphs fail explicitly; the importer cannot recover information Excel already discarded; browser preference storage is local to that browser/device. No physical mobile Safari or production-scale concurrent crew load test was performed. These limits do not prevent normal grid editing, scheduling, selected-area printing or authorized collaboration.
